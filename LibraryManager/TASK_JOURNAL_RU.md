# Журнал операций Library Manager 2.1.0

Менеджер записывает историю фоновых задач в:

`LibraryManager/reports/task_history.jsonl`

Для каждой задачи сохраняются события:
- `STARTED` — запуск с версией менеджера и выбранным путём Samples;
- `PROGRESS` — сообщения этапов выполнения;
- `SUCCEEDED` — завершение и компактная сводка результата;
- `FAILED` — ошибка задачи.

Журнал дописывается построчно, синхронно сбрасывается на диск и не перезаписывает предыдущие записи. При чтении повреждённая/оборванная JSONL-строка пропускается; журнал не исправляется и не удаляется автоматически.

Кнопка **«История задач»** показывает последнее состояние каждой задачи. Полная история остаётся доступна в JSONL-файле и может использоваться для диагностики после закрытия программы или сбоя.

Важно: история задач — это аудит выполнения, а не автоматическое возобновление. Менеджер не запускает повторно прерванные задачи без действия оператора. Повторный запуск безопасных этапов должен учитывать уже созданные manifests и существующие файлы; никакого автоматического удаления, перемещения исходников или продвижения в FACTORY журнал не выполняет.

- Связанные решения: `PPGU-MANAGER-008`, `PPGU-MANAGER-011`, `PPGU-MANAGER-012`.

### Обязательный принцип: одна физическая библиотека, два согласованных представления

1. Используется одна общая библиотека Samples в корне POP PUNK GUITAR ULTIMATE. Не создавать отдельные копии Samples для Manager и для VST3.
2. Library Manager и VST3 работают с одними и теми же исходными аудиофайлами и едиными идентификаторами assets. Manager является инструментом подготовки/проверки; VST3 — потребителем проверенных данных и файлов.
3. Сортировка по десяти разделам Manager и режимам VST3 выполняется логически через каталог, manifest и связи asset-to-mode. Не требуется физически копировать один WAV в десять папок.
4. Один asset может иметь несколько подтверждённых назначений, если это действительно подходит по музыкальным данным; каждое назначение хранится отдельно и не превращает кандидата в одобренный контент автоматически.
5. Исходные файлы остаются неизменными. Извлечённые/обработанные производные файлы хранятся в staging/derived области с точными source offsets, SHA-256 и связью с оригиналом.
6. Manager видит все состояния: новые материалы, кандидаты, review, license review, approved и rejected. VST3 по умолчанию получает только assets, прошедшие обязательные технические, музыкальные и лицензионные проверки и имеющие подтверждённую привязку/исполнительные данные для конкретного режима.
7. Нельзя смешивать кандидатный каталог Manager с runtime-каталогом VST3. Это два представления одной библиотеки и единого asset registry, а не две независимые библиотеки.
8. Пути в catalog/manifest должны быть относительными к корню PPGU либо разрешаться через единый root resolver; нельзя зашивать букву диска или абсолютный путь конкретного ПК.
9. Повторный импорт одного и того же файла должен выявляться по устойчивым признакам (включая SHA-256), без автоматического удаления, перемещения или перезаписи исходников.
10. Поиск, preview и сортировка не должны выполнять тяжёлый анализ в real-time audio callback; VST3 использует заранее подготовленные индексы/manifest и потоковую загрузку нужных ресурсов.

### Логические группы для общей библиотеки

- `Samples/FACTORY` — только вручную одобренные и лицензионно разрешённые материалы, пригодные для распространения.
- `Samples/Import Sample Guitar` — входящие пользовательские/импортированные материалы до полного аудита.
- `Samples/OTHER` — материалы, не назначенные в утверждённые режимы или требующие отдельной классификации.
- `LibraryManager/staging` и производные каталоги — результаты анализа/извлечения и временные данные; они не подменяют исходники.
- Каталог assets и Performance Manifest содержат логические назначения по десяти разделам: SAMPLE MODE, STRUMMING, ARPEGGIO, PATTERN MODE, RIFF MODE, MELODY MODE, PHRASE MODE, ONE PITCH, ARTICULATIONS, ENDING.

### Разделение допуска

- Manager может показывать и прослушивать кандидатов, но это не означает runtime readiness.
- VST3 не должен сканировать и анализировать всю библиотеку при старте или во время аудиоколбэка.
